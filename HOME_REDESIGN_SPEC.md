# VELOCE STUDIO — Homepage + Portfolio / Proof System Redesign Specification

## 0. Executive goal

Redesign the current VELOCE STUDIO homepage into a **premium, product-led software studio website** whose purpose is not simply to look good, but to function as the studio's **proof of capability and sales tool** when shown to local business owners.

The website must answer, in seconds:

1. Who are you?
2. What exactly do you build?
3. What does the software look like?
4. What will the client's own team/customer experience look like?
5. What problem does each system solve?
6. What is included when they buy it?
7. How do they contact you immediately from a phone?

The current editorial/art-directed visual identity is strong and should be preserved as a foundation: cream/off-white background, black typography, thin rules, restrained accent color, technical labels, structured layouts, and a software-studio feel.

However, the homepage must become **more visual, more product-heavy, more commercially explicit, and much more convincing on mobile**.

The website should feel closer to a **boutique software product studio** than a freelancer portfolio or generic web agency.

# 21. Mobile-first requirement — HIGH PRIORITY

This website is a sales tool that will frequently be shown **directly from a phone while standing in front of a business owner**.

Therefore:

> **Mobile is not a secondary responsive version. Mobile is a primary design target.**

## Required breakpoints

At minimum test:

- 320px
- 360px
- 375px
- 390px
- 414px
- 768px
- 1024px
- 1280px+

## Mobile rules

### Hero

- headline must remain readable;
- no horizontal overflow;
- UI visual comes immediately after CTA;
- controls remain finger-friendly.

### Navigation

- compact;
- one-tap menu;
- visible CTA.

### Project cards

On mobile, stack content:

```text
PROJECT LABEL
TITLE
PROMISE
IMAGE
MODULES
EXPLANATION
CTA
```

Do not create side-by-side tiny cards.

### Galleries

Use:

- horizontal swipe carousels;
- snap points;
- large readable visuals;
- optional dots or progress indicator.

### Manager/client toggle

Must be easy to tap.

Recommended:

`MANAGER` / `CLIENT`

as a segmented control.

### Sticky mobile CTA

Consider a bottom action bar:

`SEE SYSTEMS` | `WHATSAPP`

Do not let it cover content; add safe-area padding.

### Typography

Avoid oversized desktop typography that destroys the mobile viewport.

Headline target:

- approximately 44–58px on larger mobile if it remains readable;
- smaller dynamically where needed;
- use `clamp()` rather than hard-coded desktop sizing.

### Touch targets

Minimum comfortable target around 44px.

### Performance

Mobile should prioritize:

- fast initial render;
- lazy-loaded project images;
- modern image formats;
- no unnecessary autoplay video;
- no heavy JS animations blocking interaction.

The current reference design has the right artistic foundation but not enough visual proof.

The redesigned page should make the visitor think:

> **"This is not a guy who makes websites. These people build operating systems for businesses."**

That is the target perception.

The page should feel like the visitor has opened the front door of a real software studio.

# 37. Final instruction to Codex

Do not simply restyle the existing screenshot-based page.

**Reframe the homepage around proof of real software capability.**

The visual hierarchy should communicate:

```text
WE BUILD BUSINESS SOFTWARE
            ↓
HERE IS WHAT IT LOOKS LIKE
            ↓
HERE IS THE PROBLEM IT SOLVES
            ↓
HERE IS THE FULL SYSTEM
            ↓
HERE IS THE MANAGER EXPERIENCE
            ↓
HERE IS THE CUSTOMER EXPERIENCE
            ↓
HERE IS HOW WE BUILD IT
            ↓
LET'S BUILD YOUR VERSION
```

The final result should be exceptional enough to function as a **digital business card, portfolio, sales presentation and product catalog simultaneously**.

Most importantly, the site will often be opened by a prospect on a phone while the studio representative is standing next to them. **Design and validate the entire experience around that real-world use case.**
